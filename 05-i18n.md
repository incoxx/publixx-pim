# anyPIM — Translation Architecture (i18n)

> **Purpose:** Multilingualism at all levels. Use this skill for anything related to languages, translations, fallbacks, and multilingual APIs.

---

## Principle

Everything CAN be translatable, but nothing HAS to be. A text field "Norm" is monolingual. A product name is multilingual. The attribute controls via `is_translatable` whether values require translation.

---

## Three Levels

### Level 1: System Labels

Attribute names, type names, hierarchy names, view names, etc.

**Storage:** Fixed columns `name_de`, `name_en` + JSON column `name_json` for additional languages.

```sql
-- Example: attributes
name_de = 'Gewicht'
name_en = 'Weight'
name_json = '{"fr": "Poids", "es": "Peso", "zh": "重量"}'
```

**Affected entities:** attributes, attribute_types, unit_groups, value_lists, attribute_views, hierarchies, hierarchy_nodes, product_types, price_types, product_relation_types

**Why fixed columns + JSON?**
- de/en as fixed columns → fast queries, no JSON_EXTRACT needed
- Additional languages in JSON → flexibly extensible without schema migration

### Level 2: Master Data

Value list entries and unit abbreviations.

```sql
-- value_list_entries
display_value_de = 'Rot'
display_value_en = 'Red'
display_value_json = '{"fr": "Rouge", "es": "Rojo"}'

-- units (only when is_translatable = true)
abbreviation = 'Stk.'        -- Default/German
abbreviation_json = '{"en": "pcs.", "fr": "pce."}'
```

Units like `kg`, `mm`, `m` are international → `is_translatable = false`.
Units like `Stk.`, `Bl.` need translation → `is_translatable = true`.

### Level 3: Product Data (Attribute Values)

The critical level. Controlled via `attributes.is_translatable`.

```
Attribute: Product Name  → is_translatable = true  → One value per language
Attribute: Weight        → is_translatable = false → One value, language-independent
Attribute: Norm          → is_translatable = false → One value, technical term
Attribute: Color (Sel.)  → is_translatable = false → Key stored, display from value list
```

**Table product_attribute_values:**

| product_id | attribute_id | language | value_string |
|-----------|-------------|---------|-------------|
| prod-001 | attr-name | de | Akkubohrschrauber ProDrill |
| prod-001 | attr-name | en | Cordless Drill ProDrill |
| prod-001 | attr-name | fr | Perceuse sans fil ProDrill |
| prod-001 | attr-weight | NULL | *(value_number = 1.8)* |
| prod-001 | attr-norm | NULL | DIN EN 60745-1 |
| prod-001 | attr-color | NULL | red *(key, display from value list)* |

**Rule:** `language = NULL` for non-translated attributes. `language = 'de'/'en'/...` for translated ones.

**Unique Constraint:**
```sql
UNIQUE (product_id, attribute_id, language, multiplied_index)
```

## API: Language Control

### Header or Parameter

```
Accept-Language: de              → German
?lang=en                         → English
?lang=de,en                      → Both languages
?lang=fr                         → French (with fallback)
```

### Fallback Chain

```
Requested language → en → de → first available value
```

If `?lang=fr` and no FR value exists: try EN, then DE, then whatever is available.

### Response Format

**Single language (`?lang=de`):**
```json
{
  "productName": "Akkubohrschrauber ProDrill 18V",
  "weight": 1.8,
  "norm": "DIN EN 60745-1"
}
```

**Multiple languages (`?lang=de,en`):**
```json
{
  "productName": "Akkubohrschrauber ProDrill 18V",
  "productName_en": "Cordless Drill ProDrill 18V",
  "weight": 1.8,
  "norm": "DIN EN 60745-1"
}
```

Non-translated fields (weight, norm) appear only once. Translated fields receive a `_{lang}` suffix for each additional language.

## Saving Attribute Values (API)

```json
PUT /api/v1/products/{id}/attribute-values
{
  "values": [
    { "attribute_id": "uuid-name", "value": "Akkubohrschrauber", "language": "de" },
    { "attribute_id": "uuid-name", "value": "Cordless Drill", "language": "en" },
    { "attribute_id": "uuid-weight", "value": 1.8 },
    { "attribute_id": "uuid-norm", "value": "DIN EN 60745-1" }
  ]
}
```

The backend checks: If `attributes.is_translatable = false` and `language` is sent → 422 error. If `is_translatable = true` and no `language` → 422 error.

## Laravel: Helper Functions

```php
// Language resolution for system labels
function getLocalizedName(Model $entity, string $lang): string {
    if ($lang === 'de') return $entity->name_de;
    if ($lang === 'en') return $entity->name_en ?? $entity->name_de;
    // Additional languages from JSON
    $json = $entity->name_json ?? [];
    return $json[$lang] ?? $entity->name_en ?? $entity->name_de;
}

// Load attribute values with language
Product::with(['attributeValues' => function ($query) use ($lang) {
    $query->where(function ($q) use ($lang) {
        $q->whereNull('language')                    // Language-independent
          ->orWhere('language', $lang);               // Requested language
    });
}]);
```

## UI: Translation Workflow

| Element | Description |
|---------|-------------|
| Language switcher (global) | Dropdown top right: DE / EN / FR — changes entire view |
| Language tabs (per field) | Translated fields show tabs with flag icons |
| Translation progress | Badge: "EN: 78% translated" at product level |
| Missing translations | Filter: "Products with missing EN translation" |
| Bulk export | Multi-select → CSV with source + target language for translators |
| Copy from language | Button: "Copy from DE to EN" for initial population |
| Language flag on field | Subtle icon on translated fields |

## Configuring Languages

Available languages are defined in the system config:

```php
// config/pim.php
'languages' => [
    'de' => ['name' => 'Deutsch', 'flag' => '🇩🇪', 'is_default' => true],
    'en' => ['name' => 'English', 'flag' => '🇬🇧', 'is_default' => false],
    'fr' => ['name' => 'Français', 'flag' => '🇫🇷', 'is_default' => false],
],
'fallback_chain' => ['en', 'de'],
```
